# Feature provenance audit: per-language combined method, step 0

This file is the audit of record for step 0 of the plan in `EXPERIMENTS_PLAN.md`,
"Plan: per-language combined method". It classifies every column of four
diagnostic tables by the source of the data that enters its computation, checked
directly against the generating script rather than against any prior summary.

Classification categories: weights-only (the computation reads only the model's
weight matrix W, one row per language, one column per vocabulary token, and
nothing else); training (the computation reads only the training corpus or
corpus-derived counts, no reference to W); composite (the computation combines
weights-only and training inputs; the specific mixture is named in parentheses,
for example "composite (weights+training)"); validation (the computation reads
labels or predictions from a validation-tier evaluation set); test (the
computation reads labels or predictions from a test-tier evaluation set, used
for final reporting).

Rule for the per-language assignment rule under construction: its inputs must be
weights-only or training, or composite built only from weights and training.
Validation-derived quantities may inform evaluation strata (which languages sit
in which reporting group) but must not enter the rule itself. Test-derived
quantities are forbidden everywhere in the rule, including as strata.

The project has three evaluation datasets (`EXPERIMENTAL_SETUP.md`, "Balanced
validation protocol"): the balanced validation draw (seed 101, 188,061 lines,
used to rank candidates), the held-out remainder (45,004,014 lines, the kept
full-test pool minus draws 101 and 201, used for a pass/fail check of a ranked
candidate), and the balanced test draw (seed 201, 185,204 lines, used for final
reported numbers). Any column reading from either draw 101 or the remainder or
draw 201 is classified validation or test below, never training.

Note on the table as a whole: every column here reads only the language's own
training corpus and the gt_min matrix (itself weights+training composite), so
none of the four columns reads validation or test data. None of them is part
of the feature set named in the plan's "Assignment features, training-side
only" paragraph, so none appears in the permitted or forbidden lists below. If
a later revision of the rule adds them, this table's classification is
composite (weights+training) for all four, the same category as d_up and
up_resratio in the permitted list.
